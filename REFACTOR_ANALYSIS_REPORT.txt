二、P0 — 功能缺失(会导致编译/运行错误)
================================================================

P0-1: Parser不支持 [base, offset] 和 [base, labelref]
  文件: parser.rs 第60-73行
  现状: 解析[...]只提取base寄存器,offset丢弃
    if input.peek(syn::token::Bracket) {
        let inner; let _ = syn::bracketed!(inner in input);
        let base = parse_reg(ctx, inner)?...;
        return Ok(ast::RawArg::Reference { span, base, offset: None });
    }
  对比: RISC-V parser(108-147行)完整支持[base,offset]和[base,labelref]
  影响:
    - ld.d r4,[r3,16] -> 只解析[r3],offset 16丢失
    - workaround: opmap用[R,R,Imm]替代[R,RefOffset],语法变裸参数
    - [base,labelref]完全不可达,PC-relative load/store缺失
  状态: ❌ 未完成

P0-2: Runtime缺少error函数                                         ✅ 已完成
  文件: runtime/src/loongarch.rs
  修复: 添加3个error函数+单元测试
    - immediate_out_of_range_unsigned_32(u32)
    - immediate_out_of_range_signed_32(i32)
    - invalid_register(u8)
  commit: 614c67ed5f4c

P0-3: handle_static_reloc_inner占位实现
  文件: mod.rs 第133-139行
  现状: push(Stmt::Const(0,size)) + reloc.encode(...) -> 发出零值
  对比: RISC-V正确计算偏移并编码
  影响: 静态重定位产生错误指令
  状态: ❌ 未完成

P0-4: parse_features返回默认值
  文件: mod.rs 第141-144行
  现状: 返回ExtensionFlags::default()(只有BASE),忽略feature参数
  影响: .feature指令无效,无法启用FP/LSX/LASX
  状态: ❌ 未完成

六、新发现问题

NEW-1: bf-jit add_imm!/sub_imm!宏52位分支有符号编码bug
  文件: doc/examples/bf-jit/src/loongarch64.rs 第105-113行
  现状: add_imm!宏在52位分支中:
    let high20 = (($imm >> 32) & 0xFFFFF) as i32;
    // lu12i.w $rt, high20  -- SImm(5,20)需要有符号值
  问题: ($imm >> 32) & 0xFFFFF 产生无符号20位值(最大0xFFFFF=1048575)
        但 lu12i.w SImm(5,20) 合法范围是 [-524288, 524287]
        0xFFFFF=1048575 远超有符号范围上限524287
  暴露原因: P1-5恢复了SImm的dynamic_range_check_signed,
           此前该check被注释掉所以bug被隐藏
  影响: cargo test从workspace root有2个测试失败:
        test_add_imm (Immediate 1048575 out of range)
        test_sub_imm (Immediate 524288 out of range)
  状态: ❌ 待修复

七、遗留问题：是否应提供add_imm等便利宏给用户
================================================================

问题: LoongArch ISA缺少一条"add large immediate"指令,
      用户需要手动组合 lu12i.w+ori+lu32i.d+lu52i.d 来加载大立即数。
      bf-jit示例中的add_imm!/sub_imm!宏就是这种组合的实现,
      且当前存在有符号编码bug(NEW-1)。

分析方向:
  1. 是否应在runtime或plugin层面提供add_imm/sub_imm等便利宏?
     - 优点: 减少用户重复编写, 避免类似bug反复出现
     - 缺点: dynasm-rs设计哲学是"只提供原语,组合由用户负责",
             其他架构(aarch64/riscv)也未提供此类宏
  2. 如果不提供宏, 是否应在文档中给出正确的组合示例?
     - 修正后的bf-jit add_imm!宏可作为参考
  3. 如果提供宏, 放在哪里?
     - runtime/src/loongarch.rs 作为 #[macro_export]
     - 或作为独立crate/bf-jit的公共API

建议: 先修正bf-jit的add_imm!宏作为正确参考实现,
      后续根据用户反馈决定是否提升为官方便利宏。
